# HyperMesh .hm 容器与头部格式规范 v1

> 状态：已通过 122 个真实语料 + 8 个合成样本交叉验证（截至本版本）
> 置信度标注：✅已验证 / 🟡推断 / ❓未知

## 1. 容器层（✅ 已验证，122/122 真实文件 + 全部合成文件）

| 字段 | 偏移 | 内容 | 说明 |
|---|---|---|---|
| magic/version | 0x00 | u32 0 | 恒为 0 |
| wrapper version | 0x04 | double 5.0 | 恒为 5.0（容器格式版本） |
| gzip member | 0x0c | 1f 8b 08 00 ... | 单一 member，flags=0，OS=0x0b，ISIZE/CRC 校验通过 |

- .hm 与 .hm10 同容器；解压后为二进制数据库（载荷）
- 载荷大小 4.9KB ~ 73MB（语料范围）；未发现多 member 场景

## 2. 载荷头部（✅ 布局 / 🟡 字段语义）

载荷头 = u32 0 + double 版本号 @0x04，之后按版本分 4 代布局：

| 布局族 | DB 版本 | 特征字段 | 语料数 |
|---|---|---|---|
| v10-legacy | 10.02 | 126@0x0c，397@0x30，0.2/0.1 doubles | 2 |
| v11-classic | 11.03–11.05 | 126@0x14，u32 1@0x18，262144 或 7277@0x1c，397@0x3c，double 0.1@0x34 | 108 |
| v12-13 | 12.03–13.03 | 10000@0x14，20@0x1c | 9 |
| v14+ | 14.07–17.01，19.02(合成) | 1@0x14，3@0x18，N@0x1c（保存计数），随后字符串表 | 5 |

### v14+ 头部字符串表（✅ 合成样本解码）

记录格式：`[u32 key][u32 type][u32 strlen][bytes]`（type=5 表示 ASCII 字符串，type=7 待解），例如：
- key 11：`HyperMesh`（应用名）
- key 3/4/5：用户 `sdcll`、时间戳 `Sat Aug 22 04:57:26 2026\n`、0 值
- key 2/5/7/8/9/10/12：版本相关字符串与数值

### v11-classic 常量（✅ 跨文件一致）
- @0x14: 126(0x7e)；@0x18: 1；@0x1c: 262144(0x40000) 或 7277（与模型规模相关，待解）
- @0x34: double 0.1 恒定；@0x3c: 397（v11 主流）；@0x28: double ≈1e-4 恒定
- 尾部常量：u32 998(0x3e6)、999(0x3e7)、155(0x9b)（跨版本一致）

### 单元类型配置表（🟡 合成样本 t1）

- 表中枚举 u32 101、102、103、104、105、106、107…（每项间 8 字节间隔）
- 已验证：103 = 4 节点单元（tetra4，仓库样本 31,843 个）；104 为 1d_elements 的 400 个单元；204 也可创建 4 节点单元（语义待解）

## 8. v11.05 记录层解码结果（✅ 双变体均已 oracle 验证）

### 节点记录（v11.05，两变体统一）

52 字节/记录，节头 `[d64 tol][u32 1][u32 136][u32 count]`（可能含前置字段，需逐字节扫描+布局验证）：

| 偏移 | 内容 |
|---|---|
| +0x00 | u32 0 |
| +0x04 | u32 节点 id（变体 A 在 +0x00；两布局坐标落点相同） |
| +0x08 | u32 0 |
| +0x0C | u32 0 |
| +0x10 | d64 x |
| +0x18 | d64 y |
| +0x20 | d64 z |
| +0x28..+0x33 | 12 字节零 |

### 单元记录

**变体 A**（如 1d_elements.hm；节头 `[997][3][175][count]`）：48 字节：

`[u32 0][u32 0x01680000][行号 r1..r4][u32 0][u32 1][u32 0x70241FF5][u32 eid+1][u32 (eid+1)<<16|2][u32 0]`

**变体 B**（如 WS 仓库样本；无节头，30 字节）：

`[u32 eid][u32 0][u32 0][u16 config+256][u16 r1][u16 0][u16 r2][u16 0][u16 r3][u16 0][u16 r4][u16 0]`

config 103=3 节点（11410 个）、config 204=4 节点（20433 个）。

### 验证结果

## 9. class_id 关联实验结论（🟡 本轮）

命名块模式 `[cap=19][0][class_id][name]` 的 class_id 与实体类型（comp/mat/prop）**无一一对应**（同一 cid 同时出现 comp 与 prop，如 cid 5: BAR2 既作 comp 又作 mat；cid 17: feature_elements 既作 prop 又作 comp）。

| class_id | 观察 | 猜测 |
|---|---|---|
| 5 | comps 7 / mats 4（BAR2、base、Line、Roof…） | 普通用户 collector |
| 6 | comps 2 / mats 2（auto1） | 自动创建的 collector（auto 前缀） |
| 7 | comps 2（tetras、bumper…） | 普通 collector |
| 8 | comps 1 + 未知 5（geomety…） | 待解 |
| 10 | comps 1 / props 1（line_mesh、property1） | 待解 |
| 11 | 未知 5（Model、SectBeam…） | 模型/截面类 |
| 12/13/14/15/16 | comps（joint_parent、body_systems 为 system 实体但计入 comps） | 待解 |
| 17 | props 4 / comps 2（feature_elements） | 待解 |

结论：class_id 疑似 HM 内部 collector 子类/来源标识（auto 创建、用户创建、按配置命名等），非实体类型码。

## 10. leg_geom 几何区初步定位（🟡 本轮）

- 节点区（0x2f4–0x3c4，4 记录）之后为系统命名块区（joint_parent(13)/joint_child(12)/body_systems(13)，leg_geom 的 systems 计数为 0 但 payload 存在，疑似非活动系统）；
- 0x484+ 为几何区（线记录）：已定位线 id 引用（u32 1@0x4dc、4@0x584、2@0x5f8）与端点坐标副本（-0.85@0x48e、-1.0@0x4a6 等，与节点坐标一致），记录间为大量零填充，疑似 52 字节块的稀疏形态；线实体记录完整语义待解；
- 1d_elements 线区（0x6e4+）发现 52 字节块序列：`[索引 26..29][0x40026A2A 恒定][偏移 +256 递增×2][256][0×12][尾部索引 10/15/19/23]`——疑似显示网格/线块索引表；
- **v11.05 几何标记家族 0x81xx（✅ 本轮系统化）**：标记格式 `0x40000000 | 0x81xx`，为 v11.05 特有（v19.02 无）；0x812A 计数=点数（1d_elements 4/4、WS 148/157），疑似点记录类型；0x8126 疑似面（WS 105≈93+12、1d 1）；leg_geom（0 点 0 面）无任何 0x81xx 标记，线实体无此标记家族；点相关块结构：`[索引 26..29][0x4000812A][偏移 +256×2][256][0×12][1][尾索引 10/15/19/23]`；
- **显示网格记录（✅ 完全破解）**：52 字节记录 = `[d64 x][d64 y][d64 z][d64 0][d64 0][u32 id][u32 0][u32 0]`，与节点记录同族；1d_elements 0x1500-0x1B00 四个显示块区 = **FE 网格线框显示**（id 66-86 左边、87-105 底边、106-124 内部竖线、125+ 内部网格线，全部 0.5 步长、z=-5 平面）——显示层 = FE 网格线框记录流 + 实体元数据块链；显示点 id 与节点 id 无直接对应（显示点 997=(5,-5,-5) 恰为节点 24 坐标，机制待解）；
- **点实体链路（✅ 完全验证）**：点元数据块 ×4（`[idx 26..29][0x4000812A][off1][off1-256][256][0×12][1][尾索引 10/15/19/23]`）→ 尾索引 ↔ 0x40008126 块前导（10/15/19/23）→ 显示区偏移（0x1500/0x1700/0x1900/0x1B00）——4 个点实体与 oracle 点数一致；点实体 = 元数据块 + 显示块 + 显示记录区三层结构；
- **显示块=区段结构（✅ 本轮）**：0x40008126 块 ×4 对应 4 个 0x200 字节显示区段（0x1500/0x1700/0x1900/0x1B00），段内 52B 显示记录流 id 连续（57-65、66-105、106-124、125+）；区段 = FE 网格线框的分段存储；WS 变体 B 的 0x40008126 上下文为 `[a][b][0x40008126][大偏移][0][0]`，偏移为编码值（非字节偏移），显示结构不同待解；
- **WS 变体 B 几何坐标**：点 x/z 常见值以 d64 大量出现，但 y 值（如 -76.413612365723）不存在于载荷——存在量化/压缩转换，待解；
- **WS 点实体块（✅ 本轮定位）**：每个点 id 在载荷唯一出现一次，块结构 `[前导 u32 ~216xxx 递增][点 id][u32 1][0][0][0][数据区 24B+][尾部 u32]`；块间距不等（0x24f8→0x3036=2878B、→0x4cf0=7354B），链表/哈希组织；数据区含大 u32（3024133058 等），疑似坐标编码或指针，待解；
- **0x2X000000 标记家族（✅ 本轮）**：变体 B 特有（1d 变体 A 无）；WS 中 0x25000000 ×470、0x24000000 ×298、0x26000000 ×502、0x27000000 ×235——每点块约 3 个 0x25 标记，疑似字段分隔标记；
- **leg_geom 线端点坐标副本（✅ 本轮确认）**：几何区含线端点（节点）坐标副本，如节点 7 完整三元组 (0.42,0,-1.0)@0x7cc、-0.85@0x48e（节点 4 z）、-1.0@0x4a6/0x7dc——线几何 = 端点坐标副本 + 定义参数（含 ±1.0 方向/权重类值）；52 字节块假设对 leg_geom 几何区不成立（非对齐散布）；
- 1d_elements 的线 id 为 18,19,20,21,36,37,38,39（两组 4 条 = 两个矩形框），points 查询可用（hm_getvalue points mark=1 dataname=x/y/z/id/collector），lines 查询仅 collector 可用；
- **v19.02 点记录（合成差分验证）**：`*createpoint x y z` 有效；载荷中点为 `[u32 id][u32 0][...][d64 x][d64 y][d64 z]`（坐标在 id 后约 +0xB，非对齐；点 2=(4,5,6)@0x587、点 1=(1,2,3)@0x5b6），oracle 复核坐标一致；确认记录 = `[u32 id][u32 0][u32 0][d64 x][d64 y][d64 z]`（id 在坐标前 11 字节，非对齐），与 v11.05 节点/点记录同族；
- **v11.05 点记录（1d_elements 解码，✅ 本轮）**：点坐标 = `[u32 0][d64 x][d64 y][d64 z]`（28 字节），按点 id 顺序排列（p1=(5,-5,0)@0x20c、p2=(5,5,0)@0x248、p3=(-5,5,0)@0x36d、p4=(-5,-5,0)@0x492，oracle 复核一致）；每个点记录前有块头部（递增偏移字段 12/16/20…）；
