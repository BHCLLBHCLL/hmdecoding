# HyperMesh .hm 容器与头部格式规范 v1

## 1. 容器层（✅ 已验证，122/122 真实文件 + 全部合成文件）

| 字段 | 偏移 | 内容 | 说明 |
|---|---|---|---|
| magic/version | 0x00 | u32 0 | 恒为 0 |
| wrapper version | 0x04 | double 5.0 | 恒为 5.0（容器格式版本） |
| gzip member | 0x0c | 1f 8b 08 00 ... | 单一 member，flags=0，OS=0x0b，ISIZE/CRC 校验通过 |

- .hm 与 .hm10 同容器；解压后为二进制数据库（载荷）
- 载荷大小 4.9KB ~ 73MB（语料范围）；未发现多 member 场景

## 2. 载荷头部（✅ 布局 / 🟡 字段语义）

载荷头 = u32 0 + double 版本号 @0x04，之后按版本分 4 代布局：

| 布局族 | DB 版本 | 特征字段 | 语料数 |
|---|---|---|---|
| v10-legacy | 10.02 | 126@0x0c，397@0x30，0.2/0.1 doubles | 2 |
| v11-classic | 11.03–11.05 | 126@0x14，u32 1@0x18，262144 或 7277@0x1c，397@0x3c，double 0.1@0x34 | 108 |
| v12-13 | 12.03–13.03 | 10000@0x14，20@0x1c | 9 |
| v14+ | 14.07–17.01，19.02(合成) | 1@0x14，3@0x18，N@0x1c（保存计数），随后字符串表 | 5 |

### v14+ 头部字符串表（✅ 合成样本解码）

记录格式：`[u32 key][u32 type][u32 strlen][bytes]`（type=5 表示 ASCII 字符串，type=7 待解），例如：
- key 11：`HyperMesh`（应用名）
- key 3/4/5：用户 `sdcll`、时间戳 `Sat Aug 22 04:57:26 2026\n`、0 值
- key 2/5/7/8/9/10/12：版本相关字符串与数值

### v11-classic 常量（✅ 跨文件一致）
- @0x14: 126(0x7e)；@0x18: 1；@0x1c: 262144(0x40000) 或 7277（与模型规模相关，待解）
- @0x34: double 0.1 恒定；@0x3c: 397（v11 主流）；@0x28: double ≈1e-4 恒定
- 尾部常量：u32 998(0x3e6)、999(0x3e7)、155(0x9b)（跨版本一致）

### 单元类型配置表（🟡 合成样本 t1）

- 表中枚举 u32 101、102、103、104、105、106、107…（每项间 8 字节间隔）
- 已验证：103 = 4 节点单元（tetra4，仓库样本 31,843 个）；104 为 1d_elements 的 400 个单元；204 也可创建 4 节点单元（语义待解）

## 9. class_id 关联实验结论（🟡 本轮）

命名块模式 `[cap=19][0][class_id][name]` 的 class_id 与实体类型（comp/mat/prop）**无一一对应**（同一 cid 同时出现 comp 与 prop，如 cid 5: BAR2 既作 comp 又作 mat；cid 17: feature_elements 既作 prop 又作 comp）。

| class_id | 观察 | 猜测 |
|---|---|---|
| 5 | comps 7 / mats 4（BAR2、base、Line、Roof…） | 普通用户 collector |
| 6 | comps 2 / mats 2（auto1） | 自动创建的 collector（auto 前缀） |
| 7 | comps 2（tetras、bumper…） | 普通 collector |
| 8 | comps 1 + 未知 5（geomety…） | 待解 |
| 10 | comps 1 / props 1（line_mesh、property1） | 待解 |
| 11 | 未知 5（Model、SectBeam…） | 模型/截面类 |
| 12/13/14/15/16 | comps（joint_parent、body_systems 为 system 实体但计入 comps） | 待解 |
| 17 | props 4 / comps 2（feature_elements） | 待解 |

结论：class_id 疑似 HM 内部 collector 子类/来源标识（auto 创建、用户创建、按配置命名等），非实体类型码。

## 12. 节点段统一模型（✅ 2026-08 全语料解码）

节点段头 = [136](0x88) 标记（**非 4 字节对齐**，用字节模式 \x88\x00\x00\x00 定位）+ u32 count。头前可能有 [1]/[11]/其他字段，布局因保存版本/文件而异，但记录流统一：

| 记录布局 | 字节 | 结构 | 例 |
|---|---|---|---|
| 52B-flat | 52 | [u32 id][u32 0][u32 0][d64 x][d64 y][d64 z][u32 0x4] | body_side/truck/1d/WS |
| 92B-flat | 92 | 52B + 40B 附加（3x 关联引用 [v][0][0]） | molding1 |
| 56B-chain | 56 | [d64 x][d64 y][d64 z][u32 0x4][u32 id+1][u32 0][u32 0]（id 链式 = 字段值-1） | SEAT_MODEL(v13) |

- 解码器对每个 [136] 候选验证 60 条记录（id 有效 + 坐标合理 + **id 多样性 >= 50%** 防假命中），选最高分布局；
- v12.03 (cover.hm) 也是 52B-flat（✅ 930 节点全解）。

## 13. 元素段统一模型（✅ 2026-08 全语料解码）

元素段头 = [997][seg_id][175][count][X][Y]（175 为常量；段可多个并存，count 合计 = 元素总数）：

- **X=3（A 型，CONST 锚）**：[前置0..32B][CONST 0x70241FF5][u32 eid][u32 eid<<16|2][...0..][u32 flag<<16][n×u32 节点行号][u32 0][u32 tail]
  - flag = config+256（0x0168=cfg104, 0x0167=cfg103, 0x01CC=cfg204, 0x01DC=cfg220, 0x01CE=cfg206, 0x01D0=cfg208, 0x0138=cfg56）；
  - 前置长度 0/8/28B 等（body_side 28B、dummy 8B）；节点数 n 从 flag 后首个零推导；
  - 段内可混合 config（frame_assembly seg7: cfg103 44B + cfg104 48B 交替）；记录尾 tail 与段头 Y 一致；
- **X=2（B 型，链式 eid）**：[u32 0][u32 0][u16 flag][n×u32 节点行号][附加0..48B][u32 0][u32 next_eid]
  - eid 链 = 段头 Y（first_eid）起，每条记录尾 u32 next_eid（降序/跳变均可，如 propeller 1605→294）；
  - 附加区：fe_only(cfg220) 48B（11 个额外行号引用，语义待解）；节点数 n 需 config 查表（103→3, 104→4, 204→4, 220→8, 206→6, 208→8）；
- **行号语义**：元素节点引用一律为**节点表行号**（1-based），需经节点表映射为 id（WS/1d 行号=id 是 id 连续时的巧合）；
- WS 元素段 [997][240][175][11410][2][302871] + [997][241][175][20433][2][324028] 为 **u16 槽位变体**（节点引用 u16 交错 0），由 WS-B 30B 回退路径解码（31843/31843 ✅）。

- **v14+/17.01 节点段（✅ dummy_positioner/seat_deformer 全解 354174/354176）**：多个独立节点段，记录 = `[u32 id][u32 0][u32 子块标记 1..16][d64 x][d64 y][d64 z][u32 0×8]`（68B）或 +24B 尾部（92B，标记 3）；子块标记随段递增；无 [136] 头，由结构扫描（[0][k] 字节模式 + 30 条验证 + 单次全扩展）定位；
- **v17 元素段**：541 段全 A 型（X=3, Y=2），段 id 2000001+（大段 id 空间），全量 585546/586202（9.3s）；
- **truck 2000001+ 段**：oracle 证为 **edge 段**（edges=212489，eid 2212616 等非元素实体，记录结构类似元素，需按实体类型区分，待解）；
- **v12-13 u16 槽位型（✅ c_channel-tcl/SEAT_MODEL 互证）**：`[CONST12 0x70501FF5][u32 eid][16B 附加][u32 eid 重复][u32 0][u32 0][u16 flag][u16 n1][u16 0][u16 n2][u16 0][u16 n3][u16 0][u16 n4][u16 0][u16 0][u16 2][u16 0][u16 0]` 58B 固定；节点引用 u16 槽位（行号）；CONST 家族匹配 `(v&0xFFFF)==0x1FF5 && v>>24==0x70`（v11: 0x70241FF5, v12: 0x70501FF5）；
- **前置块头**：composites 等文件记录前有 40B 块头（`[X][1][Y][7][1][0x0A040BE6][k][Z][7][1]` 模式），CONST 在 +40；
